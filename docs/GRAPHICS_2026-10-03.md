# Graphics upload fix — 2026-10-03

The emulator is functional: the video sent by the user shows the library,
menus and intros running on the PS5. There are graphics regressions in the tested version.
This record does not claim full game compatibility.

## Evidence and cause

Video: `C:/Users/bruno/Documents/Gravando 2026-10-03 180042.mp4` (70 s).
Sonic goes from the title screen to black. When Budokai 3 is selected, the intro
alternates normal frames with green/cyan ones. The previous log, inspected in this analysis, recorded
`Vulkan shared memory: Invalid upload range` repeatedly in Sonic.

The guest physical heap allocates 4096-byte pages. `SharedMemory` used the host's
native page as the unit for uploads and for the cache: 16384 bytes on the PS5.
A 4096-byte texture can share that unit with inaccessible guest
pages. The rounded-up upload includes those pages and can be rejected
by the Vulkan backend's check. This leaves texture data missing or
stale, including planes used by the intros.

## Change

`SharedMemory` uses units of at most 4096 bytes for uploads and cache
validity. Memory protection still uses native pages. The memory callbacks
invalidate all 4096-byte graphics blocks covered by the
modified native page. Page access validation was not disabled.

The change is in `.deps/xenia-canary/src/xenia/gpu/shared_memory.cc` and in the
reproducible patch `patches/canary/xbox360ps5.patch`.

There is a second cause for Sonic stopping on black after advancing past save
creation. The test with 16384-byte native page bookkeeping reproduced
a guest exception, whose thread was left suspended. The debugger found a
write to the stack at `70E7FF30`, still protected as no-access. Allocation of the
new stack skipped the host commit with pages larger than 4096 bytes and did not
restore the protection left behind by a previous stack's guard pages.

`AllocateHostRange`, in `src/xenia/memory.cc` of the Canary core, restores the
protection when reallocating memory. For allocations smaller than the native page,
it applies the union of the permissions required by the neighboring guest pages.
The stack reallocation test failed before and passed after the fix.
Stack and faulting instruction: `build/video-review/sonic-stall/fault.txt`.

## Tests

- `xbox360ps5-runner --check-upload-pages`: four positions of a 4096-byte
  guest allocation inside a 16384-byte page, with free neighbors.
  Tests exact upload size, cache, invalidation of a 16384-byte page
  and reload. Before, four failures; after, four passes, also with the
  memory bookkeeping simulating 16384-byte native pages.
- Budokai 3, 45 s on the Linux host, with 16384-byte page bookkeeping:
  the old 16384-byte uploads reproduce the green/cyan from the video and produce
  rejections. 4096-byte uploads show the intro with normal colors, with no
  rejections in this test. Captures and logs are in
  `build/video-review/bud3-host16-16384` and `bud3-host16-4096`.
- The native PS5 build passed the mappings and relocations check:
  `build/video-review/build-ps5.log`.
- Sonic: the test simulating 16384-byte pages stopped on black before
  the reallocation fix. After both fixes, a 130 s run
  reached Soleanna with the character and scenery rendered, no pause menu
  and zero upload rejections. Capture: `sonic-phase-4096/shot-025.png`,
  log: `sonic-phase-4096/run.log`, both in `build/video-review`.
  In this test, START was limited to the first 90 s to advance through the intro,
  and A to the first 110 s; the controller stayed idle in the final stretch.

The runner accepts `XBOX360PS5_HOST_PAGE_SIZE=16384` to simulate the console's memory
bookkeeping on Linux; the actual mappings are still Linux's.
`XBOX360PS5_GPU_PAGE_SIZE=16384` reproduces the earlier uploads and `4096`
selects the fixed ones. These variables are host diagnostics and do not change
the console configuration. `XBOX360PS5_START_UNTIL=16` and
`XBOX360PS5_AUTOPRESS_UNTIL=70` limit the virtual controller to avoid pausing
continuously after entering the game.
