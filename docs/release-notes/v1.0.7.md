## TrinityX360 v1.0.7

The home screen shows `TrinityX360 v1.0.7`. It installs over v1.0.6 like an update: the title ID, the data folder and your settings stay the same. See "Upgrading from v1.0.6" at the end before you update.

**How to read the status tags below:**
- `[console]`: confirmed on a PS5.
- `[console, partly]`: part of it was seen on a PS5; the text says what is still unconfirmed.
- `[host tests]`: verified by tests on a computer (run in CI), not confirmed on the console.

TrinityX360 is based on [PS5X360](https://github.com/BrinooTk/PS5X360) by BrinooTk and on
[Xenia Canary](https://github.com/xenia-canary/xenia-canary). Trinity is the name of the Xbox 360 S motherboard.

### Games
- **GTA V no longer crashes while you drive** (fix 192) `[console, partly]`: before, the game closed after 4–8 minutes of driving around the city. In our test on `1.0.7_candidate_2` the game kept running with no crash, but how long that drive lasted was not recorded.
- **GTA V: Disc 2 finds the installed data after the disc swap** (fix 182) `[console, partly]`: after you install from "Disc 1 (Install)" and the game asks for Disc 2, it finds its installed data again instead of waiting for it for hours. On a test build the game found its data after the swap and ran on Disc 2 for about a minute; a longer session on Disc 2 is not confirmed yet.
- **Culdcept Saga: the on-screen keyboard opens** (fix 198; reported upstream as BrinooTk/PS5X360#112) `[console]`: choosing "Name" on the Create Cepter screen no longer waits for a keyboard that never comes. Other games that open the keyboard the same way should also benefit.
- **UEFA Champions League 2006-2007 should no longer close as a match loads** (issue #81; fix 188) `[host tests]`: when memory was almost full, the emulator told the game that far more memory was free than really was, so the game used it all up. The free memory a game is told now never goes past what is really free. We do not have the game, so this needs a player to confirm.
- **XNA games such as Charlie Murder: experimental changes, still not expected to run** (issue #82; fix 191) `[host tests]`: the emulator now provides some Xbox 360 system functions these games ask for, but no XNA game has been run with them, and they are still expected to stop partway or return to the menu (see Known limitations). Other games should behave as in v1.0.6.

### Kinect
- **Zumba Fitness Core finds the player and starts** (issue #68; fixes 156t, 156v, 156w) `[console]`: it no longer stays on "Searching for player...". It recognises you and goes into the game. Kinect Sports, Dragon Ball Z for Kinect, Fighters Uncaged and Dance Central 3 were checked again with this change and still recognise the signed-in profile; Kinect Sports: Season Two too, from its log. The change that lets Zumba identify you does not affect Kinect Sports or Fighters Uncaged: a player the camera loses and finds again is still the same signed-in player (checked in Kinect Sports, also after a longer break).
- **Steadier movement from the phone** (issues #74, #75; fix 169) `[console]`: movement from the phone reaches the console more steadily, with many more updates a second and fewer pauses. One failed request no longer makes the phone pair again, and a player lost for under 2 seconds keeps the same Kinect identity (in v1.0.6, such a gap could make games such as Fighters Uncaged treat you as a new player). The phone camera page is new (see "Upgrading from v1.0.6").
- **Harry Potter for Kinect reaches the menu and the lessons** (issue #76; fixes 174, 178) `[console]`: in v1.0.6 the game stopped on its loading card. On test builds of this release it got past the card to the menu, which reacts to your raised hand, and into the Year 1 Charms class. Two changes get it there after the card: the game no longer crashes when it opens the Kinect camera a second time, after the raised hand (174), and games that need the Kinect microphone now get an emulated one that hears silence, so the "Kinect required" message no longer comes back (178). The menus and most lessons can be played by hand (for the Charms lessons that wait for a spoken spell, see the next items). Voice commands do not react. This needs "Camera motion (research)" on.
- **Harry Potter for Kinect: the speech start-up no longer waits for a microphone** (issues #74, #76; fix 170) `[host tests]`: the game's speech start-up now fails at once instead of waiting for a Kinect microphone. This is aimed at the stop on the loading card at about 27 seconds. On the console the game got past the loading card on test builds with this change, but the change itself did not act in those runs, so its effect is not confirmed.
- **Harry Potter for Kinect: Charms lessons without a microphone** (issue #76; fix 187) `[host tests]`: a new game patch, "Spoken spells time out without a microphone", is in the game's Patches tab and on by default. Five Charms lessons that waited forever for a spoken spell now time out like the others: stay silent for about a minute (the game reminds you twice), and the lesson skips the spoken part and goes on to the wand pose. It has not been tried on a PS5 yet.
- **Nike+ Kinect Training gets past "GET ATHLETE FIT"** (issue #77; fixes 171, 193) `[console]`: the game now gets the Xbox Fitness service and a default body profile (175 cm, 75 kg, male), so it no longer waits forever. It now goes on to the Kinect sign-in, the fitness body profile and the first drill (HURDLE STEP). The game runs without the new emulated Kinect microphone, which it does not work with; nothing needs to be set. The drill's "MOVE ONTO THE MARKER" step does not work yet (see Known limitations).
- **The motion panel shows where the game sees you** (issue #77; fix 194) `[console, partly]`: with a phone as the Kinect, the motion panel on the TV has a new "Play-space map" (Controls, per game, on by default). The left half shows the game's skeleton of you, upright. The right half is a map from above with the camera's view, the spot most games want (green) and you as a dot. A line underneath gives the game's distance and a hint: "Step back", "Step closer", "Move left", "Move right", "Show your whole body to the camera", "The camera sees you sideways: stand the phone upright" or "Good spot". On the console the map, the distance, "Good spot" and the dot moving with sideways steps were seen; the other hints were not checked one by one.
- **No "stand the phone upright" hint while you bend** (fix 194b) `[host tests]`: the motion panel no longer shows the sideways hint during bends, planks, push-ups or toe touches; only a body lying across the picture, as from a phone on its side, brings it up. It has not been tried on a PS5 yet.
- **A figure of you instead of a grey picture** (issue #76; fix 185) `[host tests]`: with "Camera picture for the game" off in the app's settings (Controls; off by default), games that show the Kinect camera (Harry Potter's camera window, Kinect Sports replays) show a simple figure of you on a dark background instead of a flat grey or green rectangle. No camera image leaves the phone. With it on, and the phone page's own "Camera picture" switch on too, the phone's picture is used as before; until that picture arrives, the grey shows. On the console the camera opened in this mode in Kinect Sports and Nike+ Kinect Training, but the figure itself has not been seen on screen yet.
- **L3 + R3 re-centres once** (fix 196) `[console, partly]`: a short press of L3 + R3 re-centres the phone camera once, instead of many times in a row. Holding L3 + R3 to keep your last pose (the emergency pose) still did nothing in that test.
- **The emergency pose should start sooner** (fix 196b) `[host tests]`: holding L3 + R3 should bring your last pose back once the phone has lost you for half a second, instead of after 3 seconds. When only another user's controller is connected, its L3 + R3 works too. It has not been tried on a PS5 yet.

### Picture and performance
- **Halo: Reach starts at 1x under "Automatic"** (fix 197) `[console]`: at 2x it ran out of video memory after a while and the picture filled with noise. Under "Automatic" it now starts at 1x, and the picture stayed clean after several minutes. Choosing "2x (1440p, demanding)" yourself still gives 2x.
- **GTA IV at 2x: no thin lines around the minimap** (issue #69; fixes 168, 168b) `[console, partly]`: the thin bright line around the minimap frame and the thin vertical line near the left edge are gone, with no new lines in the HUD, menus, the in-game phone, interiors or cutscenes. Nothing needs to be set: this is built into the app for GTA IV. It was checked on test builds before the release candidates, and not again on them. Nothing changes at 1x.
- **Leaving a game is faster** (issue #69; fixes 173b, 173c) `[console]`: when no new shader was built during the session, leaving a game no longer waits to save the shader cache again. For GTA IV at 2x this wait was about 12 seconds, and up to 30 seconds on a busy drive; it is now a few milliseconds. Leftovers of a save cut short at the previous exit are cleaned up.
- **Less wasted time in games that signal between threads very often** (issue #78; fix 180) `[console]`: games whose threads wake each other thousands of times a second spend much less time on it in the emulator. In Tekken Tag Tournament 2 and Virtua Tennis 3 each wake-up got about 10 to 35 times cheaper, with no hang; their frame rate did not change. This is meant to help Spider-Man: Web of Shadows, which was not tried. In this release the new behaviour is the default (fix 180b) `[host tests]`.
- **Fewer freezes from small temporary files** (issue #63; fix 172) `[host tests]`: when a game keeps creating and deleting small temporary files on a slow drive, those files now move to memory, so the game should not pause for up to a second at each one. This is aimed at the stutter in Kinect Sports: Season Two darts, and is not confirmed on the console yet.

### Settings and the guide
- **New option: "Unlimited write speed (root)"** (issue #80; fix 186) `[console]`: under Settings, in the System category, off by default. It removes the console's per-app write-speed limit: after about 1.5 GB in one app session, writes drop to about 2 MB/s, which makes the GTA V install slow. With it on, the app asks for root when it starts, through the console's ELF loader (for example etaHEN's), using the small helper `lapy.elf` that comes in the package. It takes effect from the next app start. Without a loader that answers, or if root is refused, the app starts as usual without root, about 8 seconds later than normal; with no loader on your console, leave the option off. Your theme, settings and data stay the same. While the option is on, the helper writes `lapy-helper.log` in `/data/homebrew/PPSA83600` at each start. On firmware 13.60 with etaHEN, root was granted, writes of 2 GiB ran at about 140–220 MiB/s with no slowdown, and GTA IV played normally; with the option off, the app runs as before.
- **Per-game emulator settings files work again** (issue #70; fix 166) `[console]`: a game's own settings file, `<TITLE ID>.config.toml`, is read again. You can put one in `/data/homebrew/PPSA83600/game-configs/` over FTP. Settings files that come with the app (Fable III, and new in this release GTA IV and Nike+ Kinect Training) still apply; a file of your own in the data folder is read after them, so it wins.
- **A per-game switch for one-pixel lines at 2x** (issue #69; fix 168) `[console]`: these two lines in a game's settings file remove thin one-pixel lines along HUD boxes and screen edges at 2x:
  ```toml
  [GPU]
  resolution_scale_half_pixel_host = true
  ```
  It is off by default and has no menu entry. GTA IV has it on out of the box.

### Library and home screen
- **The controller stays with the PS5 menus** (issue #85; fix 190) `[console]`: while the PS5 control center or quick menu is open, or the app is in the background, the controller no longer moves the library or the game behind it, and the button that closes the system menu no longer reaches the app. Games still see the controller as connected.
- **The recent list keeps its games** (fix 181) `[host tests]`: the recently played list no longer shrinks to a single game when a game starts without the library (a game with its own start options restarting the app into itself, the guide's "Restart game", or a game started from the console's home screen). A multi-disc game such as GTA V also keeps the disc you played last. This was a known limitation in v1.0.6.

### For bug reports
- **More information in the logs** (fixes 156s, 167, 169, 173, 180) `[console]`: the logs now say which body a Kinect game picks as its player (and, for Zumba Fitness Core, its play area), give a phone-link report (frames a second and pauses), time each step of saving the shader cache when you leave a game, and give per-thread wake-up counts for games that signal often. With a file named `resolve-trace.txt` in `/data/homebrew/PPSA83600`, the log also lists each kind of render-to-texture copy once (at most 400 lines a session).
- **Why an L3 + R3 hold did nothing** (fix 196b) `[host tests]`: the log now says why holding L3 + R3 did not start the emergency pose.

### Known limitations
- Everything listed for v1.0.6 still applies unless it is fixed above. Still open from earlier releases: Virtua Tennis 3 players are invisible in some matches (issue #17), Battlefield 3 shows brief black squares near smoke in the carrier-deck intro, and the Kinect Sports replay preview with the phone's camera picture is not smooth.
- **Nike+ Kinect Training: "MOVE ONTO THE MARKER"** in HURDLE STEP is never accepted, so the drills cannot go on (issue #77). Following the Play-space map does not help. Most likely the game needs a kind of Kinect depth image that the emulator does not provide yet; we plan to look at this for v1.0.8. Workouts are not saved, and the body profile is a fixed default that cannot be changed.
- **Nike+ Kinect Training runs without the emulated Kinect microphone** to avoid a black screen after its intro. This is a workaround for this one game; the cause is planned for v1.0.8. A settings file of your own for this game is read after the built-in one, so a `[Kinect]` section with `kinect_microphone = true` in it can bring the black screen back.
- **The L3 + R3 emergency pose** (holding L3 + R3 to keep your last pose) has not been seen working on the console yet. The change in this release that should make it work (196b) is not tested on the console. The TV hint "No player seen" still appears only after 3 seconds without a body.
- **Harry Potter for Kinect**: the emulated microphone hears only silence, so spoken spells and voice commands never work. The Charms patch that lets lessons go on without a spell is not tested on the console yet, and it covers only the USA/Europe release it was made for.
- **Fighters Uncaged**: the menu cursor still jumps a little, and the punch on the start screen can take a few tries.
- **The phone as the Kinect** still depends on your Wi-Fi: the motion panel switches to "Motion: no phone connected" after 3 seconds without updates.
- **The figure of the player** that replaces the grey camera picture has not been checked on screen yet. With "Camera picture for the game" on, the old grey shows until the phone's picture arrives.
- **Kinect Sports: Season Two**: darts loads and plays, but some stutter can remain; the change aimed at it (172) is not confirmed on the console. The other sports are not confirmed yet (issue #63).
- **Kinect Adventures**: its changes are still tested only on a computer, not on the console (issue #63).
- **Kinect games at 2x chosen by hand**: memory is still tight, so stutter or replay artifacts can appear after a while (issue #73). "Automatic", the default, starts these games at 1x.
- **XNA games, such as Charlie Murder** (issue #82), are still not expected to run: this release has only experimental changes for them, and full support is not planned yet. If a game that worked in v1.0.6 stops working in v1.0.7, please report it.
- **UEFA Champions League 2006-2007** (issue #81) and **Spider-Man: Web of Shadows** (issue #78) were not tried on the console with this release. Reports are welcome.
- **Halo: Reach at 2x chosen by hand** can still fill the picture with noise after a while.
- **"Unlimited write speed (root)"** is experimental. It was tried only on firmware 13.60 with etaHEN. Root is not granted on every start: if a long write is still slow with the option on, restart the app. It changes the app's own process rights while it runs, so use it at your own risk. Without it, the GTA V install still slows to about 2 MB/s after about 1.5 GB in one app session, and restarting the app brings the full speed back.
- **The controller and the PS5 menus**: checked only with the control center on firmware 13.60. On a system that cannot tell whether its menu is on top, the controller works as in v1.0.6.
- **Firmware 5.50**: a player on firmware 5.50 told us that every game closes at start with builds of this fork. The cause is not known yet, and nothing in this release changes it. If you are on 5.50, please open an issue here with your logs.
- **GTA V on Disc 2 after the swap** was checked only for about a minute. **Culdcept Saga**: only the keyboard opening is confirmed, not the rest of the Create Cepter screen.
- **GTA IV at 2x keeps its cache files on the drive**, because the memory goes to the sharper picture. The driving pauses could come back in long sessions at 2x. At 1x the cache is in memory.
- **Leaving a game** still waits for the shader cache to be saved when new shaders were built in that session: up to 30 s once the console's write limit for the app session has been reached.
- **Per-game settings files** have no menu: nothing in the app lists or edits them, and some options in them apply only when the emulator starts.
- **"Automatic" changes the scale only from a game's next start**: a game that struggles at 2x finishes the current session at 2x.
- **Red Dead Redemption at 2x** chosen by hand ran at about 20–30 FPS in v1.0.5. "Automatic" starts it at 1x.
- **"Frame rate limit (screen)" at 40** needs a 120 Hz output. This release does not ask the PS5 for 120 Hz, so 40 is not applied on a 60 Hz output (issue #49).
- **Dance Central 3** needs you to upload the game's music keys, which are not included. The game needs a restart after the upload.
- **A game's own saved setting still wins over the recommended settings**: if you set FIFA Street's or GTA V's own "Image readback by the game" earlier, that value is kept. Reset that game's own settings to use the recommended one.
- **Minor**: the launcher can pause for about 2 s while it scans the library at start. The first line of a game log still says "PS5X360".

### Upgrading from v1.0.6
- **Install it over v1.0.6 as before.** Use the whole package (`PPSA83600.ffpkg`, `.ffpfsc` or `.zip`, only one of them), never `eboot.bin` alone. The title ID (PPSA83600) and the data folder (`/data/homebrew/PPSA83600`) are the same, and its `contentVersion` is `01.007.000`, so the console sees v1.0.6 as an older install.
- **Your settings stay where they are.** Settings, per-game settings, the recent list, game folders, covers and your other files stay in `/data/homebrew/PPSA83600`. Nothing is moved this time.
- **Per-game settings files now apply.** If you put a `<TITLE ID>.config.toml` file in `/data/homebrew/PPSA83600/game-configs/` earlier, it takes effect from this release. Check that it still says what you want.
- **Phone camera**: the phone camera page is new. If your phone still shows the old page, open it again from the QR code.
- **Halo: Reach** under "Automatic" now starts at 1x. If you chose 1x or 2x in its own settings, your choice is kept.
- **Thread wake-ups**: the faster way games wake their threads (fix 180) is now the default. If a game runs worse than in v1.0.6, put a file named `event-pulse.txt` with the word `old` in `/data/homebrew/PPSA83600` to go back to the v1.0.6 behaviour, and please report the game. This applies to every game; delete the file to use the new behaviour again.

### Source code
Built by `tools/source-1.0.2/assemble.py` with fixes 01–13 (with 08b), 20–39, 41–43, 45–52, 54–67, 69, 71–91 (with 90b), 93 (93b–93i), 95–99 (99b), 101–123, 125, 126, 128–135, 137, 139–141, 143–154, 155c, 156 (156b–156w), 159, 162a, 162c, 162d, 162f, 162h, 163, 165–174, 178, 180–182, 185, 186, 188, 190–192, 194, 196–199 (letters included) from `tools/source-1.0.2/fixes`; the GTA IV and Nike+ Kinect Training settings (168b, 193) are files in `assets/config` and the Harry Potter for Kinect patch (187) is a file in `assets/patches`. The corresponding source, toolchain source and scripts are release assets, as for v1.0.6 (`PS5X360-1.0.7-source.tar.xz`, `PS5X360-1.0.7-toolchain-source.tar.xz`, `TrinityX360-1.0.7-scripts.tar.gz`). The whole is GPL-3.0; PS5X360 code stays under MIT (`licenses/PS5X360-MIT.txt`) and Xenia under BSD-3-Clause. The code in `eboot.bin` that talks to the optional root helper (`port/vendor/lapy`, adapted from prospero-win) is under LGPL-2.1-or-later (`licenses/LAPY-LGPL-2.1.txt`). The helper `lapy.elf`, built from PS5-Lapy-JB-Daemon, is a separate program in the package, not linked into `eboot.bin`. It links the payload SDK's GPL-3.0-or-later runtime, so it is GPL-3.0-or-later as a whole; its own parts are LGPL-2.1-or-later and MIT (`licenses/LAPY-MIT.txt`). Their upstream source at the pinned commits is in `PS5X360-1.0.7-toolchain-source.tar.xz`, and the build and relinking notes are in `tools/source-1.0.2/lapy-daemon/NOTICE.md`.
